# หน้าแรกสาธารณะและหน้าวิเคราะห์ของเจ้าหน้าที่

ระบบหลักนอกโฟลเดอร์ demo ใช้ธีมงานสหกรณ์ที่เรียบและเป็นทางการ โดยจัดหน้าจอตามผู้ใช้งานดังนี้

## หน้าแรก — index.php

หน้าแรกเปิดให้บุคคลทั่วไปเห็นว่าเป็นระบบรวบรวมยางของสหกรณ์ ไม่ใช่เครื่องมือวิเคราะห์ข้อมูล มีชื่อระบบ ชื่อสหกรณ์ ขั้นตอนการทำงาน ทางเข้าสำหรับเจ้าหน้าที่ และบริการข้อมูลสมาชิก

ข้อมูลที่แสดงเป็นสรุปอ่านอย่างเดียว:

- ราคาประกาศล่าสุดพร้อมวันที่รอบ
- ปริมาณ มูลค่ารับซื้อ จำนวนผู้ส่ง และจำนวนรายการของรอบล่าสุด รวมทุกลาน
- กราฟปริมาณและมูลค่าของวันที่มีรายการรับซื้อล่าสุด สูงสุด 12 วัน โดยบอกจำนวนวันที่มีข้อมูลจริง
- ปริมาณ มูลค่า จำนวนรายการ และจำนวนวันที่มีรายการสะสมทั้งหมด แยกขอบเขตจากกราฟย้อนหลัง
- ตารางรับซื้อรายลานในรอบล่าสุด
- รายการล่าสุดที่ชั่งแล้วสูงสุด 20 รายการ เรียงเวลายืนยันผลชั่งล่าสุด ต้องมีผลชั่งจริง และไม่นับรายการยกเลิก
- รายการล่าสุดที่พิมพ์ใบเสร็จแล้วสูงสุด 20 รายการ ใช้ชุดข้อมูลและลำดับเดียวกับหน้า printed_receipts.php
- ทั้งสองส่วนแสดงชื่อผู้ส่ง ลาน กระสอบ และน้ำหนัก ไม่แสดงยอดเงิน วันที่รับซื้อ หรือประเภทผู้ส่ง เลขรายการแสดงใต้ชื่อ และไม่มีข้อมูลกระสอบแสดง —
- ประกาศวันวางยาง/ชั่ง และสรุปรอบที่อัปเดตทุก 5 นาทีตามเงื่อนไขเดิม

ไม่มีตัวเลือกช่วงวันที่ ลาน หรือเครื่องมือวิเคราะห์ละเอียดบนหน้าแรก ค่า date_from/date_to/lan ใน URL ไม่เปลี่ยนสรุปสาธารณะ เมนูบนหน้าแรกของผู้ที่ยังไม่เข้าสู่ระบบแสดงเฉพาะหน้าหลัก ข้อมูลสรุป บริการสมาชิก และทางเข้าของเจ้าหน้าที่

## หน้าวิเคราะห์ — collection_analysis.php

ต้องเข้าสู่ระบบเจ้าหน้าที่ก่อน ผ่านปุ่มวิเคราะห์การรวบรวมใน dashboard.php หรือเมนูจัดการระบบ ผู้ที่ยังไม่เข้าสู่ระบบจะถูกส่งไปหน้า login และไม่เห็นข้อมูลวิเคราะห์

เลือกวันที่รับซื้อเริ่มต้น/สิ้นสุดและลาน แล้วกดวิเคราะห์ข้อมูล หากไม่เลือกวันที่จะแสดงทุกวันที่มีรายการ วันที่เริ่มต้น/สิ้นสุดเป็นขอบเขตแบบรวมวันนั้นด้วย กราฟ ตัวเลข และตารางรายวันใช้ตัวกรองเดียวกัน

- ปริมาณและมูลค่า: รวม ru_quantity และ ru_value ของรายการที่ไม่ยกเลิก
- ยอดสุทธิและยอดหัก: รวม ru_netvalue และ ru_expend ที่บันทึกอยู่ ไม่ใช่สถานะการจ่ายเงินจริง
- ราคาเฉลี่ยถ่วงน้ำหนัก: มูลค่ารับซื้อรวม ÷ ปริมาณรวม ไม่ใช้ราคาปัจจุบันคูณรายการย้อนหลังหรือเฉลี่ยราคาลานแบบน้ำหนักเท่ากัน
- ค่าเฉลี่ย 3 วันรับซื้อ: ใช้สามวันที่มีรายการล่าสุดรวมวันที่นั้น เริ่มแสดงเมื่อครบสามวัน ไม่ใช่สามวันปฏิทิน
- อัตราเปลี่ยนแปลง: เทียบวันที่มีรายการล่าสุดกับวันที่มีรายการก่อนหน้า ไม่แสดงเปอร์เซ็นต์เมื่อไม่มีฐานหรือปริมาณวันก่อนหน้าเป็นศูนย์
- ผู้ส่งยาง: สมาชิกนับจากเลขสมาชิก ทั่วไปนับจากชื่อ ไม่นับข้อมูลระบุผู้ส่งที่ว่าง และนับไม่ซ้ำภายในวันเท่านั้น ไม่รวมยอดรายวันเป็นจำนวนคนไม่ซ้ำตลอดช่วง
- กราฟแสดงเฉพาะวันที่มีรายการ ไม่เติมวันที่ไม่มีข้อมูลเป็นศูนย์ ไม่มีการพยากรณ์หรือสร้างข้อมูลตัวอย่างในระบบจริง
- รวมรายการรับซื้อที่ไม่ยกเลิก โดยยังไม่แยกสถานะอนุมัติ

หน้าวิเคราะห์ไม่จำกัดข้อมูลไว้เพียง 200 กลุ่มวัน/ลาน ขนาดข้อมูลสรุปขึ้นกับจำนวนวันและลาน ฐานข้อมูลยังต้องรวมรายการรับซื้อที่ตรงตัวกรอง เลือกช่วงวันที่เพื่อลดปริมาณการแสดงผลได้

## การรักษาข้อมูลเดิม

มูลค่ารายลานบนหน้าแรกใช้ SUM(ru_value) จากยอดที่เก็บไว้ ไม่คูณด้วยราคาประกาศล่าสุด จึงตรงกับรายการจริงเมื่อราคาถูกแก้ภายในวัน

ไม่แก้สูตรหรือขั้นตอนการชั่ง ยอดหัก อนุมัติ และใบเสร็จ ไม่เปลี่ยนฐานข้อมูลจริง และไม่แก้โฟลเดอร์ demo ธีมโหลดเฉพาะ media=screen ไม่เพิ่ม CSS นี้เข้า HTML ที่สร้าง PDF

## ไฟล์ที่ต้องนำไปด้วยเมื่อติดตั้ง

- index.php, collection_analysis.php, dashboard.php, header.php, footer.php และหน้าทำงานที่อ้างธีมใหม่
- collection_analytics.php, public_collection_feeds.php และ partials ทั้งโฟลเดอร์
- assets/css/operations-theme.css, assets/css/public-overview.css, assets/css/collection-analytics.css
- assets/js/public-overview.js, assets/js/collection-analytics.js
- assets/vendor/chart-4.4.1.umd.min.js พร้อมใบอนุญาต
- fonts/Sarabun-*.ttf ตามไฟล์เดิมของโปรเจกต์

กราฟโหลด Chart.js จากไฟล์ในระบบ ไลบรารีอื่นยังคงวิธีโหลดเดิม จึงไม่ได้เปลี่ยนทั้งระบบให้ใช้ออฟไลน์

## ตรวจสอบ

```sh
php tests/collection_analytics.php
python3 tests/analytics_integration.py
```

integration test ใช้ PHP และคำสั่ง MariaDB ในเครื่องพัฒนา สร้าง instance ชั่วคราวแบบไม่มี TCP ใช้เฉพาะ schema จาก SQL เดิม เติมข้อมูลสมมติ 220 วัน/สองลานและบัญชีทดสอบแยก ไม่คัดลอกหรืออ่าน config ระบบจริงหรือ demo และลบข้อมูลทั้งหมดเมื่อจบ

ตรวจหน้าแรกว่ามีเฉพาะสรุปอ่านอย่างเดียวและกราฟย้อนหลังสูงสุด 12 วัน ตรวจหน้าวิเคราะห์ว่าเข้าไม่ได้ก่อน login และตัวกรองมีผลหลัง login ตรวจ partials ว่าเรียกตรงผ่านเว็บไม่ได้ ตรวจข้อมูล 440 กลุ่มวัน/ลาน ยอดราคา รายการยกเลิก และข้อมูลบุคคลว่าง ชุดทดสอบกระบวนการเดิมยังผ่าน 196 ข้อ และการคำนวณ 12 ข้อผ่าน

ยังต้องตรวจภาพและการใช้งานบนมือถือจริงเพิ่มเติม

ตรวจตารางล่าสุดเพิ่มเติม: จำกัดสูงสุด 20 รายการ ลำดับใหม่ก่อน ตัดรายการยกเลิก ผลรวมถูกต้อง และกรณีมีน้อยกว่า 20 รายการหรือไม่มีข้อมูล

ตรวจข้อมูลล่าสุดเพิ่มเติม: ไม่แสดงยอดเงิน แสดงชื่อโดย escape HTML ดึงจำนวนกระสอบจากวางยางผ่านผลชั่ง และไม่แทนค่ากระสอบที่ไม่ทราบเป็นศูนย์

## การจัดหน้าจอสำหรับบุคคลทั่วไป

- จอกว้างตั้งแต่ 1100px: สรุปรอบล่าสุดเต็มแถว ตามด้วยบล็อกชั่งแล้วและพิมพ์ใบเสร็จแล้วคู่กันในแถวเดียว กราฟทั้งสองอยู่คู่กันในแถวถัดไป และยอดสะสมอยู่คู่กับสรุปรายลาน ประกาศที่กำลังแสดงจัดเป็นสองคอลัมน์ด้วย
- ส่วนแนะนำระบบและปุ่มสำหรับสมาชิกคงอยู่ด้านบน เพื่อให้หาทางเข้าใช้งานได้ทันที
- ตาราง 20 รายการล่าสุดเป็นตารางเดียวเสมอ ไม่แบ่งรายการเป็นสองตารางหรือสองคอลัมน์
- จอแคบกว่า 1100px: บล็อกทั้งหมดเรียงเป็นคอลัมน์เดียว โดยสรุปรอบล่าสุดและรายการล่าสุดมาก่อน
- จอแคบกว่า 992px: ซ่อนส่วนกราฟทั้งหมด รวมชื่อหัวข้อและพื้นที่ว่าง และไม่โหลด Chart.js หรือสร้างกราฟสำหรับหน้าแรก
- หากขยายหน้าจอจนมีพื้นที่พอ จะโหลดและแสดงกราฟได้โดยไม่ต้องเปิดหน้าใหม่ หากย่อกลับ จะหยุดกราฟและคืนพื้นที่ให้ข้อมูลสรุป
- กราฟของหน้าเจ้าหน้าที่ collection_analysis.php คงพฤติกรรมเดิม การปรับนี้ใช้เฉพาะหน้าแรกสาธารณะ

ตรวจ CSS/PHP/JavaScript syntax ผ่าน และทดสอบการโหลดกราฟตามหน้าจอ การคืนทรัพยากรเมื่อย่อจอ การขยายกลับโดยไม่ดาวน์โหลดซ้ำ และการเปลี่ยนจอระหว่างโหลดไลบรารีแล้ว


## สองเหตุการณ์บนหน้าแรก

การแสดงผลไม่ใช่คิวที่ย้ายรายการออกจากส่วนหนึ่งไปอีกส่วนหนึ่ง:

1. เมื่อมีผลชั่งยืนยันใน tbl_wang_weighing รายการเข้าเกณฑ์ส่วนชั่งแล้ว เรียง weighed_at ใหม่ก่อน แล้วตัดสินลำดับซ้ำด้วย weighing_id และ ru_id
2. เมื่อรายการอยู่ในชุดข้อมูลของหน้าพิมพ์ใบเสร็จแล้ว รายการเข้าเกณฑ์ส่วนพิมพ์ใบเสร็จแล้ว โดยเรียก issued_rubber_receipts และเลือก 20 รายการแรก จึงใช้เงื่อนไขและลำดับเดียวกับหน้านั้น
3. รายการที่ผ่านทั้งสองขั้นตอนยังมีสิทธิ์ปรากฏทั้งสองส่วนภายใต้ขีดจำกัดล่าสุด 20 รายการของแต่ละส่วน ไม่ลบจากส่วนชั่งเพียงเพราะออกใบเสร็จแล้ว
4. อนุมัติหรือบันทึกยอดหักเสร็จอย่างเดียวยังไม่ถือว่าอยู่ในหน้าพิมพ์ใบเสร็จแล้ว ต้องมีบันทึกการออกใบเสร็จตามระบบเดิม การตรวจไม่เกี่ยวกับการยืนยันกระดาษออกจากเครื่องพิมพ์จริง
5. รายการเก่าที่ไม่มีผลชั่งไม่ถูกนับเป็นชั่งแล้ว แต่หากมีใบเสร็จอยู่ก็แสดงในส่วนพิมพ์ใบเสร็จแล้วเช่นเดียวกับหน้าต้นทาง

ทดสอบสองส่วนแยกกัน: จำกัด 20 รายการ ลำดับชั่งตามเวลาที่ชั่งจริง ชุดและลำดับใบเสร็จตรงกับฟังก์ชันของหน้าเดิม รายการเดียวแสดงสองส่วนได้ ยอดกระสอบ/น้ำหนักแต่ละส่วนไม่ปนกัน และสถานะยังไม่ชั่ง → ชั่งแล้ว → พร้อมพิมพ์แต่ยังไม่ออกใบเสร็จ → ออกใบเสร็จ → ยกเลิก แสดงถูกต้อง ชุดทดสอบขั้นตอนงานเดิมผ่าน 196 ข้อ

- ตารางหน้าแรกใช้หัวตารางเขียวอ่อน แถวข้อมูลสลับสีขาว/เขียวอ่อน เส้นแบ่งชัด และตัวอักษรเข้ม โดยกำหนดสีเซลล์เฉพาะหน้าแรกเพื่อไม่ให้รูปแบบส่วนกลางกลบสีพื้น
