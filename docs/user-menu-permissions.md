# สิทธิ์เมนูรายบัญชี

## วิธีใช้งาน

เข้าสู่ระบบด้วย admin → จัดการระบบ → บัญชีผู้ใช้ / สิทธิ์เมนู → แก้ไข / สิทธิ์ จากนั้นเลือกเมนูและบันทึก หรือกำหนดระหว่างสร้างบัญชีใหม่ได้

เลือกได้เฉพาะ 5 เมนูหลักตามหน้าที่: วางยาง, ชั่งยาง, อนุมัติหลังชั่ง, บันทึกยอดหัก และพิมพ์ใบเสร็จ รายงาน วิเคราะห์ จัดการสมาชิก และศูนย์งานสหกรณ์ให้ admin เข้าถึง ไม่อยู่ในตัวเลือกมอบหมายสิทธิ์

- admin เข้าถึงทุกเมนูเสมอ การกำหนดราคา ตรวจสอบประวัติรวม ยกเลิกรายการ จัดการบัญชี และเมนู admin เดิมยังสงวนให้ admin
- บัญชี user เดิมที่ยังไม่เคยกำหนดสิทธิ์ ใช้เมนูงานทั่วไปเดิมได้จนกว่า admin จะบันทึกการกำหนดสิทธิ์
- บันทึกโดยไม่เลือกเมนูใด คือไม่ให้ใช้เมนูงานภายใน ยังเข้าสู่ระบบและดูหน้าสาธารณะได้
- บัญชีสมัครเองผ่าน register เริ่มต้นโดยไม่มีสิทธิ์เมนูงาน ต้องรอ admin กำหนด การส่งค่า role หรือ permissions แทรกไปกับการสมัครไม่เพิ่มสิทธิ์
- สิทธิ์มีผลกับคำขอถัดไป ไม่ต้องออกจากระบบ เมนูบนหน้าที่เปิดค้างอาจต้องโหลดหน้าใหม่เพื่อแสดงชุดเมนูใหม่
- หน้าเข้าสู่ระบบเลือกปลายทางที่ใช้ได้ หากไม่มีเมนูงานจะกลับหน้าแรกพร้อมข้อความติดต่อ admin
- การระงับบัญชี ถอนสิทธิ์ หรือเปลี่ยนระดับจาก admin เป็น user มีผลกับ session เดิมด้วย

## การบังคับสิทธิ์

`permission_functions.php` กำหนดรายการเมนูและเส้นทาง ส่วน `functions.php` เรียกตรวจสิทธิ์ก่อนโค้ดของหน้าเว็บทำงาน ตรวจทั้ง URL, GET, POST และ AJAX บัญชีที่เข้าสู่ระบบแล้วแต่ไม่มีสิทธิ์ได้รับ HTTP 403 ส่วนคำสั่งที่ยังไม่เข้าสู่ระบบได้รับ 401 หรือไปหน้า login เมื่อเปิดหน้าเว็บ

เมนูใน header และลิงก์งานใน dashboard แสดงตามสิทธิ์ ไม่ใช้เพียงการซ่อนปุ่มเป็นตัวป้องกัน หน้าแรก กระดานสถานะสาธารณะ และ QR ยังคงเปิดดูได้โดยไม่เข้าสู่ระบบ

เส้นทางที่งานใช้ร่วมกันได้รับการจัดกลุ่มไว้ เช่น ผู้บันทึกวางยางค้นหาสมาชิกเพื่อเลือกรายการได้ โดยไม่ได้สิทธิ์เพิ่ม/แก้ไขสมาชิก และผู้อนุมัติหรือผู้บันทึกยอดหักยังเปิดใบเสร็จจากขั้นตอนงานของตนเองได้ โดยไม่จำเป็นต้องได้เมนูรายการใบเสร็จทั้งหมด

การอนุญาตเป็นระดับเมนูและงาน ไม่ใช่การจำกัดตามลานหรือรายสมาชิก เงื่อนไขล็อกข้อมูลหลังชั่ง การแก้วันที่เฉพาะ admin ราคาที่ตรึงเมื่อชั่ง การอนุมัติ และการออกใบเสร็จยังใช้เงื่อนไขเดิม

## ฐานข้อมูล

ระบบสร้าง `tbl_user_menu_permissions` อัตโนมัติเมื่อเริ่มใช้สิทธิ์ เก็บรายการเมนู ผู้แก้ล่าสุด และเวลาที่แก้ ไม่เปลี่ยนโครงสร้าง `tbl_user` หรือข้อมูลรวบรวมยาง หากต้องสร้างผ่านแผงโฮสต์เอง ใช้ `docs/user-menu-permissions.sql`

สิทธิ์ว่างที่บันทึกแล้ว (`[]`) ต่างจากบัญชีเดิมที่ยังไม่มีแถวกำหนดสิทธิ์ การบันทึกบัญชีและสิทธิ์ใช้ transaction เดียวกัน หากบันทึกสิทธิ์ไม่สำเร็จจะย้อนกลับการเปลี่ยนข้อมูลบัญชีด้วย การลบบัญชีลบข้อมูลสิทธิ์ที่เกี่ยวข้องด้วย และไม่อนุญาตให้ลบบัญชี admin จากหน้ารายการ

## ไฟล์ระบบที่ต้องอัปโหลดทั้งชุด (13 ไฟล์)

1. `permission_functions.php` — ใหม่: รายการเมนู ฐานข้อมูลสิทธิ์ และตัวตรวจสิทธิ์กลาง
2. `functions.php` — โหลดและบังคับสิทธิ์ก่อนทำงาน
3. `header.php` — เมนูร่วมสำหรับมือถือและจอใหญ่
4. `partials/operations-navigation.php` — ใหม่: เมนูเจ้าหน้าที่ตามสิทธิ์
5. `user_form.php` — ตัวเลือกสิทธิ์และ CSRF
6. `user_save.php` — บันทึกบัญชีและสิทธิ์ร่วมกัน ตรวจข้อมูลและป้องกันการระงับ admin ที่กำลังใช้งาน
7. `users.php` — ทางเข้าจัดการสิทธิ์และ CSRF สำหรับลบบัญชี
8. `user_delete.php` — ตรวจ CSRF ป้องกันลบ admin และล้างสิทธิ์บัญชีที่ลบ
9. `login.php` — เลือกหน้าเริ่มต้นตามสิทธิ์
10. `register.php` — บัญชีสมัครเองยังไม่มีสิทธิ์งาน
11. `dashboard.php` — แสดงทางเข้าเมนูตามสิทธิ์
12. `index.php` — ทางเข้าศูนย์งานตามสิทธิ์และข้อความสำหรับบัญชีที่ยังไม่มีเมนู
13. `assets/css/user-permissions.css` — ใหม่: หน้าจอเลือกสิทธิ์แบบ responsive

อัปโหลดภายใต้ `/test/` ก่อนทดสอบ จากนั้นใช้ชุดเดียวกันที่ `/` ได้ คง `db_config.php` ของแต่ละตำแหน่งไว้ แพ็กไม่มีไฟล์ตั้งค่าฐานข้อมูลหรือข้อมูลบัญชีทดสอบ ต้องอัปโหลดไฟล์ใหม่ครบทั้งชุด โดยเฉพาะ `permission_functions.php` และ `partials/operations-navigation.php`

## การตรวจสอบ

- `php tests/user_permissions.php`: การเลือกสิทธิ์ สิทธิ์ว่าง ค่าเดิม บทบาทจากฐานข้อมูล เมนูที่อนุญาต ปลายทาง login และหน้าสาธารณะ
- `python3 tests/user_permissions_http.py`: สร้างฐานข้อมูลและ PHP server ทดสอบแยก ตรวจการ login จริง เมนู การเรียก URL/POST ตรง การให้/ถอนสิทธิ์ใน session เดิม สมัครเอง CSRF บัญชี inactive การถอน admin และการแยก `/test/` กับ `/` แล้วลบฐานข้อมูลทดสอบ
- `php tests/weighing_integration.php`, `php tests/public_dashboard.php` และ `python3 tests/deployment_paths.py`: กระบวนการงานและหน้า QR เดิม
- ทดสอบเพิ่มเติม: จำลองการบันทึกสิทธิ์ล้มเหลวแล้วย้อนกลับบัญชี ตรวจการลบบัญชีพร้อมสิทธิ์ และตรวจ UI ที่ 320–1440px

เมนูใหม่ในอนาคตต้องเพิ่มการจัดกลุ่มใน `rts_route_permissions()` เสมอ เส้นทาง PHP ที่ไม่ได้จัดกลุ่มจะสงวนให้ admin จนกว่าจะกำหนดนโยบาย
