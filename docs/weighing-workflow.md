# วางยาง → ชั่งน้ำหนัก → ใส่ยอดหัก

## ขั้นตอนใช้งาน

1. บันทึกวางยางจากหน้าวางยางเดิม ระบุผู้ส่งยาง กลุ่ม เลขที่ ชั้น ลาน และจำนวนกระสอบ
2. เปิด `weigh_wang.php` จากปุ่ม **ชั่งน้ำหนัก** เลือกวันที่วางยางและลาน
3. กรอกน้ำหนักสุทธิเป็นกิโลกรัม ทศนิยมไม่เกินสองตำแหน่ง แล้วเลือกรอบราคา
4. เจ้าหน้าที่ชั่งกด **ยืนยันน้ำหนัก** หนึ่งรายการวางยางมีผลชั่งหนึ่งรายการ แก้น้ำหนักได้ก่อนบันทึกยอดหัก ระบบจะกลับหน้าชั่งลานเดิมเพื่อทำรายการถัดไป และส่งรายการเข้าคิวรอบันทึกยอดหัก
5. เจ้าหน้าที่ผู้รับผิดชอบยอดหักใช้บัญชีของตนเองเปิด `rubbers.php` เลือกรายการรอบันทึก ระบุยอดหักหุ้น เงินกู้ หนี้ระยะสั้น เงินฝาก สินเชื่อการค้า และประกัน แล้วบันทึก

เก็บผู้ชั่ง (`weighed_by`) และผู้บันทึกยอดหัก (`deductions_saved_by`) แยกกัน พร้อมแสดงชื่อผู้รับผิดชอบทั้งสองขั้นตอน รายการรอบันทึกยอดหักมองเห็นข้ามเจ้าหน้าที่ผู้ชั่งได้ เพื่อให้เจ้าหน้าที่อีกส่วนรับช่วงต่อ

วันที่วางยาง วันที่ชั่ง และวันที่รอบราคาเป็นคนละข้อมูลกัน วันที่รายการรับซื้อ `ru_date` ใช้วันที่ของรอบราคาที่เลือก น้ำหนักไม่หักภาชนะซ้ำ เพราะเจ้าหน้าที่กรอกน้ำหนักสุทธิมาแล้ว

## ข้อมูลและการเชื่อมโยง

- `tbl_wangyang`: รายการต้นทาง จำนวนกระสอบ และ `wang_weight` สำหรับแสดงน้ำหนักที่ยืนยันแล้ว
- `tbl_wang_weighing`: ผลชั่งจริง ผู้ชั่ง เวลาชั่ง น้ำหนักสุทธิ รอบและราคาที่ใช้ เชื่อม `wang_id` และ `ru_id` แบบหนึ่งต่อหนึ่งด้วย UNIQUE
- `tbl_rubber`: น้ำหนักใน `ru_quantity` มูลค่ายาง ยอดหัก และยอดสุทธิ สำหรับรายงานเดิม

การยืนยันใช้ transaction และล็อกรายการวางยางก่อนตรวจซ้ำ การสร้างผลชั่ง รายการรับซื้อ และการอัปเดตน้ำหนักต้นทางสำเร็จพร้อมกัน หากส่วนใดล้มเหลวจะ rollback ทั้งชุด

ราคาถูกเก็บเป็นค่าคงที่ขณะชั่ง การเปลี่ยนราคาต้นฉบับภายหลังไม่เปลี่ยนราคาของรายการชั่งเดิม และหน้ากรอกยอดหักใช้ราคานี้ทั้งแสดงผลและคำนวณฝั่ง server

รายการที่เชื่อมผลชั่งแล้วไม่เปิดให้แก้ข้อมูลวางยางหรือลบ และ `rubbers.php` ไม่รับน้ำหนักหรือข้อมูลผู้ส่งที่ส่งแก้จาก browser ฟิลด์ยอดหักยังแก้ไขได้ตามสิทธิ์เดิม

## การติดตั้งและข้อมูลเดิม

ต้องมี `tbl_rubber` และ `tbl_price` จากฐานข้อมูลเดิมก่อน ตารางผลชั่งจะสร้างอัตโนมัติเมื่อเข้าใช้งาน ผู้ใช้ฐานข้อมูลจึงต้องมีสิทธิ์ CREATE และ REFERENCES สำหรับการติดตั้งครั้งแรก

สร้างตารางล่วงหน้าได้จากโฟลเดอร์โปรเจกต์:

```sh
php -r 'require "functions.php"; ensure_weighing_schema(db());'
```

รายการรับซื้อเดิมคงอยู่และแก้ยอดหักผ่านหน้าระบบเดิมได้ แต่ไม่มีการจับคู่กับรายการวางยางโดยเดาจากชื่อหรือเลขสมาชิก การเพิ่มรายการใหม่ใน `rubbers.php` เปลี่ยนเป็นเริ่มจากหน้าชั่ง การแก้น้ำหนักที่ยืนยันผิดและการยกเลิกรายการชั่งยังไม่มีหน้าจอรองรับ จึงควรตรวจน้ำหนักและรอบราคาก่อนยืนยัน

## การตรวจสอบ

```sh
php tests/weighing_integration.php
```

สคริปต์สร้างฐานข้อมูลทดสอบชื่อสุ่มโดยไม่คัดลอกข้อมูลบุคคล และลบฐานข้อมูลที่สร้างในตอนจบ ต้องใช้บัญชีที่มีสิทธิ์ CREATE/DROP DATABASE ทดสอบค่าน้ำหนักผิด รอบราคาผิด การส่งน้ำหนักและคำนวณเงิน การแยกวันที่วางยางกับรอบราคา การยืนยันซ้ำ ราคาที่เก็บไว้ การกันลบ และ rollback เมื่อเกิดข้อผิดพลาดระหว่าง transaction

## สถานะงานและหน้าสรุป

- หน้าวางยางแสดงยอดงานวันนี้: รอชั่งน้ำหนัก / ชั่งแล้ว รอยอดหัก / บันทึกยอดหักแล้ว กดเพื่อดูรายการในสถานะนั้นได้
- หน้าชั่งเปิดที่ **รอชั่งน้ำหนัก** โดยดึงรายการวางยางที่ยังไม่มีผลชั่ง รวมงานค้างทุกวัน เลือกวันที่และลานเพื่อจำกัดข้อมูล หรือกดการ์ดเพื่อดูสถานะอื่น
- หน้ายอดหักเปิดที่ **ชั่งแล้ว รอบันทึกยอดหัก** รวมทุกรอบราคา แสดงการ์ดรายการรอบันทึก / บันทึกแล้ว / รายการเดิม / ทั้งหมด พร้อมป้ายสถานะแต่ละแถว
- เมื่อบันทึกยอดหักสำเร็จ ระบบบันทึกเวลาและผู้บันทึกใน `deductions_saved_at` / `deductions_saved_by` พร้อมกับยอดเงินใน transaction เดียวกัน ยอดหักศูนย์บาทก็ถือว่าทำเสร็จเมื่อกดบันทึก
- การ์ดยอดรวมคำนวณจากข้อมูลทั้งหมดตามตัวกรอง ไม่ใช่เฉพาะรายการในหน้าปัจจุบันของ pagination
- งานชั่งที่มีอยู่ก่อนเพิ่มสถานะจะเริ่มเป็นรอบันทึกยอดหัก เพราะไม่มีประวัติยืนยันย้อนหลังให้ตรวจสอบ กดบันทึกยอดหักอีกครั้งเพื่อยืนยันสถานะได้ รายการรับซื้อเก่าที่ไม่มีผลชั่งเชื่อมอยู่จะแสดงเป็นรายการเดิม
- ปุ่ม Excel ของตารางแสดงในมุมมอง **ทั้งหมด** ซึ่งตรงกับเงื่อนไขที่ตัวส่งออกรองรับ

## เลือกลานก่อนชั่ง

เมื่อเปิด `weigh_wang.php` ต้องเลือกลาน 1–4 ก่อนจึงจะโหลดรายการและสรุปสถานะ หน้ารายการแสดงเฉพาะลานที่เลือก มีปุ่มเปลี่ยนลานโดยคงวันที่และสถานะไว้ ไม่มีตัวเลือกทุกลานในหน้าชั่ง และ server ตรวจว่ารายการวางยางตรงกับลานที่เลือกก่อนบันทึกน้ำหนัก

## ยืนยันยอดหักก่อนพิมพ์ใบเสร็จ

รายการที่ยังรอบันทึกยอดหักเริ่มด้วยช่องยอดหักว่าง ต้องกรอกอย่างน้อยหนึ่งช่อง (กรอก 0 ได้) แล้วกดบันทึก ช่องอื่นที่เว้นว่างบันทึกเป็น 0.00 เมื่อสำเร็จจึงเปิดให้พิมพ์ใบเสร็จ การเรียก URL ใบเสร็จโดยตรงของรายการที่ยังไม่บันทึกยอดหักจะถูกปฏิเสธด้วย HTTP 403 รายการเก่าที่บันทึกก่อนมีระบบชั่งยังพิมพ์ได้ตามเดิม

## ล็อกหลังออกใบเสร็จ

เมื่อสร้าง PDF ใบเสร็จสำเร็จ ระบบบันทึกเวลา ผู้รับผิดชอบ และข้อมูลใบเสร็จครั้งแรกใน `tbl_rubber_receipts` หลังจากนั้นบัญชีเจ้าหน้าที่ทั่วไปแก้ไขยอดหักไม่ได้ แม้ส่ง POST โดยตรง บัญชี admin ยังแก้ไขผ่าน `rubbers.php` ได้ โดยเก็บชื่อและเวลาที่แก้ไขล่าสุดพร้อมรักษาข้อมูลใบเสร็จครั้งแรกไว้ การพิมพ์ซ้ำไม่ปลดล็อกและไม่ทับข้อมูลครั้งแรก รายการที่ออกใบเสร็จแล้วลบไม่ได้

การออกใบเสร็จและการแก้ไขล็อกรายการรับซื้อใน transaction ป้องกันการแก้ไขแทรกระหว่างออกใบเสร็จ ประวัติการพิมพ์ก่อนเพิ่มระบบล็อกไม่สามารถตรวจย้อนหลังจากข้อมูลเดิมได้ การล็อกเริ่มเมื่อสร้าง PDF ผ่านระบบนี้สำเร็จครั้งแรก

## ล็อกหน้าวางยางตามขั้นตอนปลายทาง

หน้าวางยางและหน้าจัดการวางยางแสดงป้ายล็อกตามสถานะ ชั่งน้ำหนักแล้ว / บันทึกยอดหักแล้ว / ออกใบเสร็จแล้ว โดยไม่แสดงปุ่มแก้ไขหรือลบของรายการนั้น API ตรวจข้อมูลจริงซ้ำเสมอ หากมีการเปลี่ยนสถานะหลังโหลดหน้า คำขอแก้ไขหรือลบจะถูกปฏิเสธ (409) และไม่ใช้ SDK fallback ข้ามการปฏิเสธจาก server

## แก้น้ำหนักก่อนบันทึกยอดหัก

ในหน้าชั่ง เลือกสถานะชั่งแล้ว รอยอดหัก เปิดแก้ไขน้ำหนักของรายการ แล้วบันทึกน้ำหนักใหม่ ระบบใช้ราคาเดิมและอัปเดตน้ำหนักในผลชั่ง รายการวางยาง และรายการรับซื้อ พร้อมคำนวณเงินใหม่ใน transaction เดียว เก็บชื่อและเวลาแก้ไขล่าสุดแยกจากผู้ชั่งครั้งแรก เมื่อบันทึกยอดหักแล้ว (รวมถึงยืนยัน 0 บาท) จะไม่สามารถแก้น้ำหนักจากหน้าชั่งได้

หากเจ้าหน้าที่ยอดหักเปิดฟอร์มก่อนแก้น้ำหนัก ระบบจะอ่านน้ำหนักล่าสุดอีกครั้งภายใต้การล็อกรายการขณะบันทึก เพื่อไม่ให้น้ำหนักเก่าจากฟอร์มย้อนทับผลชั่งที่แก้ไขแล้ว

## ยอดวางยางในหน้าชั่ง

การ์ดวางยางแล้ว (รอชั่งน้ำหนัก) นับและแสดงเฉพาะรายการที่ยังไม่บันทึกน้ำหนัก ไม่ใช่ยอดสะสม เมื่อบันทึกน้ำหนัก รายการจะออกจากการ์ดแรกและไปอยู่ชั่งแล้ว รอยอดหัก เมื่อบันทึกยอดหักแล้วจะย้ายไปบันทึกยอดหักแล้ว ทั้งสามสถานะไม่ซ้ำกัน

## หน้าชั่งบนสมาร์ตโฟน

รายการวางยางแสดงเป็นการ์ดแนวตั้งแทนตารางกว้าง มีช่องน้ำหนักขนาดใหญ่และแป้นพิมพ์ตัวเลข รอบราคา และปุ่มบันทึกเต็มความกว้าง จอใหญ่ตั้งแต่ 1200 พิกเซลแสดงรายการเป็นแถวโดยวางช่องน้ำหนัก รอบราคา และปุ่มบันทึกข้างกัน แท็บเล็ตแสดงสองคอลัมน์ และมือถือแสดงคอลัมน์เดียว ตัวกรองวันที่ การแก้น้ำหนัก และประวัติผู้บันทึกเปิดดูได้ตามต้องการ โดยยังต้องเลือกลานก่อนเข้ารายการและใช้เงื่อนไขล็อกข้อมูลเดิม
